# 회의실 예약 현황 대시보드 기획서

## 1. 배경 — 어떤 업무가 왜 비효율적인가

당사는 3개 층에 회의실 12개를 운영하고, 예약은 사내 그룹웨어에서 받습니다.
총무팀이 매주 월요일 오전에 지난주 예약 내역을 CSV로 내려받아 수기로 집계하고 있습니다.

- 집계 대상: 주당 평균 예약 건수 약 240건
- 소요 시간: 담당자 1명이 주 3시간 (엑셀 피벗 재작성 + 노쇼 대조)
- 연간 환산: 약 156시간 / 인건비 환산 약 480만 원
- 추가 손실: 노쇼(예약 후 미사용) 비율을 제때 파악하지 못해, 실제로는 비어 있는
  회의실이 "예약됨"으로 표시되어 주당 20~30건의 반려가 발생

가장 큰 문제는 집계가 **주 1회 사후에만** 이뤄진다는 점입니다. 총무팀은 이번 주에
어느 회의실이 얼마나 비었는지를 다음 주 월요일에야 알 수 있습니다.

## 2. 왜 기성 도구로는 안 되는가

검토한 대안과 배제 사유입니다.

| 대안 | 배제 사유 |
|------|-----------|
| 엑셀 피벗 유지 | 지금 하고 있는 방식. 매주 수기 재작성이 문제의 원인 |
| 그룹웨어 기본 통계 | 예약 건수만 제공. 체크인 로그와 대조한 **노쇼 판정 불가** |
| 기성 회의실 예약 SaaS | 예약 기능 자체를 대체하는 제품. 그룹웨어를 걷어내야 해서
  사내 결재·조직도 연동이 전부 끊김. 도입 비용도 연 1,200만 원대 |

핵심은 **그룹웨어 예약 CSV와 출입 게이트 체크인 로그를 대조**해야 노쇼를 판정할 수
있는데, 두 데이터가 서로 다른 시스템에 있고 사번 형식도 다르다는 점입니다. 이 대조
규칙은 당사 고유 업무 규칙이라 기성 제품이 제공하지 않습니다.

## 3. 만들 것

두 CSV를 올리면 노쇼를 판정해 회의실별·요일별 실사용률을 보여주는 웹 대시보드.

### 핵심 기능

| # | 기능 | 설명 |
|---|------|------|
| 1 | CSV 업로드 | 예약 내역·체크인 로그 2개 파일 업로드 |
| 2 | 사번 정규화 | 그룹웨어(`E-00123`)와 게이트(`123`) 형식 차이를 흡수 |
| 3 | 노쇼 판정 | 예약 시작 후 15분 내 체크인 없으면 노쇼로 분류 |
| 4 | 실사용률 집계 | 회의실별·요일별 실제 사용 시간 / 예약 시간 |
| 5 | 결과 표·그래프 | 화면에서 바로 확인 |
| 6 | 집계 결과 내려받기 | CSV로 저장해 주간 보고에 첨부 |

### 성공 기준

- 예약 CSV 240건 + 체크인 로그를 올렸을 때 **10초 이내**에 집계 완료
- 노쇼 판정 결과를 총무팀이 수기 집계한 값과 대조해 **오차 5% 이내**
- 담당자 작업 시간 주 3시간 → **주 20분 이내**

### 예외 처리

- 필수 컬럼(`예약일시`, `회의실`, `사번`)이 없으면 어떤 컬럼이 빠졌는지 표시
- 빈 파일·헤더만 있는 파일은 안내 문구 표시 후 중단
- 체크인 로그가 없으면 노쇼 판정은 건너뛰고 예약 집계만 수행

## 4. 도입·운영

- 배포: 사내망 서버에 Streamlit으로 단일 프로세스 기동 (기존 사내망 정책 준수)
- 데이터: 두 CSV 모두 담당자가 기존 권한으로 이미 내려받고 있는 파일. 신규 권한 불필요
- 개인정보: 사번은 집계 후 폐기, 화면에 개별 사번 노출하지 않음
- 유지보수: 총무팀 담당자 1명이 CSV만 올리면 되고, 규칙 변경은 상단 상수 수정으로 대응
- 확장: 층별 필터, 월간 리포트 자동 발송은 2차로 검토

## 5. 범위 밖

- 예약 기능 자체(그룹웨어 유지)
- 실시간 연동(수동 CSV 업로드로 시작)
- 모바일 전용 화면
