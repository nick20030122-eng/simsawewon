# 인공지능 심사위원 AI JUDGE — 사용 방법

> **이 안내는 참가팀·이용자를 위한 문서입니다.**
> 별도 설치나 API 키 없이, 웹 브라우저만 있으면 이용할 수 있습니다.

---

## 1. 이 서비스는 무엇을 하나요?

**인공지능 심사위원 AI JUDGE**는 여러분의 **GitHub 공개 레포 주소 하나**를 받아,
레포 안의 기획서와 실행 코드를 AI가 읽고 점수와 코멘트를 알려 주는
**사전 점검·참고용** 도구입니다.

- 파일을 따로 올리지 않습니다. **레포 주소만** 넣으면 됩니다.
- 각 항목은 **0~100점**입니다.
- Pass/Fail(합격·불합격)은 표시하지 않습니다.
- **최종 심사 결과를 대신하지 않습니다.** 제출 전 스스로 점검하는 용도로 활용해 주세요.

### 심사 트랙이 둘로 나뉩니다

접수 화면에서 **기관용**과 **기업용** 중 하나를 고릅니다.

| 트랙 | 무엇을 기준으로 보나요? |
|------|------------------------|
| **기관용** | 공공기관·지자체 업무 현장의 문제 해결에 적절한 기획인지 |
| **기업용** | 사내 업무 개선 효과가 있는지, 직접 만들 이유가 있는지 |

> **두 트랙은 채점 기준이 다르므로 점수를 서로 비교할 수 없습니다.**
> 80점끼리라도 같은 잣대로 매긴 점수가 아닙니다.

### 심사 분야는 2개, 세부 항목은 6개

**제1분야는 트랙마다 다릅니다.**

| 트랙 | 제1분야 | 세부 항목 3개 |
|------|---------|---------------|
| 기관용 | 공공기관 적합성 | 페인포인트 명확성 / 해결 방향 적절성 / 공공 현장 적용 가능성 |
| 기업용 | 사업 타당성 | 문제·비용 구체성 / 자체 구축 정당성 / 도입·운영 현실성 |

**제2분야는 두 트랙 공통입니다.**

| 제2분야 | 무엇을 보나요? | 세부 항목 3개 |
|---------|----------------|---------------|
| 의도 구현도 | 기획서에 적은 내용이 코드에 실제로 구현됐는지 | 핵심 요구사항 구현 / 성공 기준 충족 / 기획 의도 일치 |

분야 점수는 세부 3개 항목의 평균이고, **종합 점수는 두 분야 점수의 평균**입니다.

### 왜 기획서와 코드를 함께 보나요?

이 서비스는 한쪽만 보는 것이 아니라 **둘을 서로 대조**합니다.

| 비유 | 설명 |
|------|------|
| 기획서 | 「무엇을 만들기로 했는지」 적어 둔 **설계도** |
| 실행 코드 | 「실제로 무엇을 만들었는지」 보여 주는 **완성품** |

설계도와 완성품이 다르면 「의도 구현도」에서 감점됩니다.
그래서 기획서와 코드가 **같은 프로젝트**를 가리켜야 합니다.

## 2. 어디서 이용하나요?

웹 브라우저(Chrome, Edge 등)로 아래 주소에 접속합니다.

| 페이지 | 주소 | 하는 일 |
|--------|------|---------|
| **홈** | https://innocurve-judge.vercel.app | 시작 화면 |
| **심사 접수** | https://innocurve-judge.vercel.app/evaluate | 레포 주소 제출·심사 |
| **채점 기준** | https://innocurve-judge.vercel.app/criteria | 트랙별 평가 기준 미리 보기 |

상단 메뉴 **홈 · 심사 접수 · 채점 기준**으로도 이동할 수 있습니다.

## 3. 제출 전 준비 — 레포에 무엇이 있어야 하나요

### ① 기획서 파일

심사 시스템이 레포에서 **자동으로 찾습니다.** 아래 이름 중 하나로 두세요.

```
PLAN.md   기획서.md   planning.md   PLAN.txt   기획서.txt
```

- 하위 폴더에 있어도 찾지만, **루트에 가까울수록** 먼저 찾습니다.
- **기획서 파일이 없으면 두 분야 모두 0점**입니다.
  두 분야 다 기획서를 근거로 채점하기 때문입니다.

### ② 실행 코드

- **언어는 상관없습니다.** Python, JavaScript, TypeScript, HTML, Java, Go 등
  일반적인 소스 파일을 인식합니다.
- 앱 진입점(`app.py`, `main.py`, `index.html`, `app.js` 등)이 있으면 먼저 읽습니다.
- 최대 25개 파일까지 수집합니다.

### ③ 레포는 반드시 **공개(public)** 여야 합니다

비공개 레포는 읽을 수 없습니다. 심사 전에 공개로 바꿔 두세요.

> README는 **더 이상 채점 대상이 아닙니다.** 있어도 되고 없어도 되며, 점수에
> 영향을 주지 않습니다.

## 4. 이용 순서

### ① 채점 기준 먼저 읽기 (권장)

**채점 기준** 페이지에서 내 트랙의 세부 항목 6개가 무엇을 보는지 확인해 보세요.
점수가 「왜 이렇게 나왔는지」 이해하려면 기준을 미리 아는 것이 도움이 됩니다.

### ② 심사 접수 화면으로 이동

메뉴에서 **심사 접수**를 누릅니다.

### ③ 트랙 선택

**기관용 / 기업용** 중 하나를 고릅니다. 소속과 과제 성격에 맞는 쪽을 선택하세요.

### ④ 레포 주소 입력

```
https://github.com/사용자명/레포이름
```

형식이 맞지 않으면 입력칸 아래에 안내가 표시됩니다.

### ⑤ 심사 시작

1. **「심사 시작」** 버튼을 **한 번** 누릅니다.
2. 보통 **40초~2분** 정도 걸립니다.
3. **기다리는 동안 버튼을 연속으로 누르지 마세요.**

화면에 진행 단계가 표시됩니다.

```
자료 수집 → 적격성 검증 → 앙상블 채점 → 점수 집계 → 후기 작성
```

**왜 연속 클릭이 문제인가요?**
한 번 누를 때마다 서버에 새 심사 요청이 들어갑니다. 여러 번 누르면 같은 작업이
동시에 여러 번 돌아가서 대기 시간이 늘거나 일시적 한도 초과 오류가 날 수 있습니다.

### ⑥ 결과 확인

심사 결과서에는 다음이 표시됩니다.

- **종합 점수**와 분야 2개 점수 (트랙 배지도 함께 표시)
- **세부 채점표** 6행 — 항목별 점수, 반복 채점 표본, 편차
- **감점 요인** (최대 5개)
- **심사위원 총평** (3문장)
- 수집한 레포 정보 — 브랜치, 파일 개수, 기획서를 찾은 경로

**점수 해석 팁**

| 상황 | 의미 |
|------|------|
| 제1분야만 낮음 | 기획서의 문제 정의·근거를 보완하면 됨 |
| 의도 구현도만 낮음 | 기획서와 코드 내용이 어긋났을 가능성 |
| 두 분야 모두 0점 | 기획서 파일을 못 찾았거나 개발 기획서가 아닐 가능성 |
| **자체 구축 정당성**이 특히 낮음 (기업용) | 기성 도구로 대체 가능해 보인다는 뜻 |

### ⑦ 음성으로 듣기 (선택)

결과 화면의 **음성 브리핑 재생** 버튼으로 심사 코멘트를 들을 수 있습니다.
음성은 부가 기능이므로, 실패해도 **글 결과는 그대로** 유효합니다.

## 5. 채점이 어떻게 이뤄지나요

### 앙상블 채점 — 같은 항목을 여러 번 봅니다

AI는 같은 글을 읽어도 매번 조금씩 다른 점수를 낼 수 있습니다.
이 서비스는 **항목마다 3회 독립적으로 채점한 뒤 중앙값**을 최종 점수로 씁니다.
그래서 같은 제출물을 다시 넣어도 점수가 크게 흔들리지 않습니다.

### 판정 불안정 표식

3회 채점 간 **편차가 큰 항목**에는 「판정 불안정」 표식이 붙습니다.
표식이 있으면 사람 심사위원이 직접 확인해 볼 것을 권한다는 뜻입니다.

### 부적격 분야 0점

무의미한 입력이나 개발 기획서가 아닌 글은 **해당 분야만 0점**으로 처리하고
사유를 결과서에 적습니다.

## 6. 더 정확한 점검을 위한 팁

1. **기획서와 코드는 반드시 같은 프로젝트**여야 합니다.
2. 기획서에 **성공 기준과 예외 처리**를 적어 두세요. 「성공 기준 충족」 항목이
   그 내용을 코드와 대조합니다.
3. 기획서에 **없는 기능**을 코드에만 잔뜩 넣으면 「기획 의도 일치」에 불리합니다.
4. **기업용 참가자**는 「이걸 왜 엑셀·노션·기성 SaaS 대신 직접 만들어야 하는가」를
   기획서에 꼭 적으세요. 이 근거가 없으면 **자체 구축 정당성**이 크게 깎입니다.
5. 문제의 규모를 **시간·건수·금액**으로 환산해 적으면 「문제·비용 구체성」에 유리합니다.

## 7. 자주 묻는 질문

**Q. AI가 제 앱을 직접 실행해 보나요?**
A. 아니요. 레포에서 수집한 **글(기획서·코드)** 만 읽습니다.

**Q. README를 꼭 써야 하나요?**
A. 아니요. README는 채점 대상이 아닙니다. 다만 협업을 위해 쓰는 것은 여전히 좋습니다.

**Q. 같은 레포를 여러 번 넣으면 점수가 같나요?**
A. 항목마다 3회 채점해 중앙값을 쓰기 때문에 대체로 비슷합니다. 다만 AI 특성상
조금씩 달라질 수 있습니다.

**Q. 트랙을 잘못 골랐어요.**
A. 다시 접수하면서 트랙을 바꿔 제출하면 됩니다. 점수는 트랙별로 따로 해석하세요.

**Q. 비공개 레포도 되나요?**
A. 안 됩니다. **공개(public)** 레포만 읽을 수 있습니다.

**Q. Python이 아니어도 되나요?**
A. 됩니다. 언어와 무관하게 일반적인 소스 파일을 인식합니다.

**Q. 팀원에게 오늘 겪은 문제를 설명하려면?**
A. **주의사항_및_문제해결.md**에 증상·원인·해결과 설명용 예시 문장이 정리되어 있습니다.
