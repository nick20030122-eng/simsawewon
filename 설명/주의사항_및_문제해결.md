# 주의사항 및 문제 해결

> 화면에 뜬 문구를 그대로 찾아보세요. **왜** 생기는지와 **어떻게** 푸는지를 함께 적었습니다.

---

## 1. 시작 전 꼭 알아둘 것

| 항목 | 내용 |
|------|------|
| 제출물 | **GitHub 공개 레포 주소 하나** (파일 업로드 아님) |
| 필수 파일 | 레포 안의 `PLAN.md` 또는 `기획서.md` |
| 트랙 | 접수 화면에서 **기관용 / 기업용** 선택 |
| 소요 시간 | 보통 **40초~2분** |
| 버튼 | **한 번만** 누르기 |
| 점수 성격 | 참고용. 최종 심사를 대신하지 않음 |

> **두 트랙의 점수는 서로 비교할 수 없습니다.** 채점 기준이 다릅니다.

## 2. 레포를 읽지 못하는 경우

### 「레포를 찾을 수 없습니다. URL이 맞는지, 공개(public) 레포인지 확인해 주세요.」

**왜 생기나요?**
GitHub가 404를 돌려준 상황입니다. 주소 오타이거나, 레포가 **비공개**여서
바깥에서는 존재조차 보이지 않는 경우입니다.

**어떻게 푸나요?**
1. 브라우저 시크릿 창으로 그 주소를 열어 보세요. 안 열리면 비공개입니다.
2. GitHub 레포 → Settings → General → 맨 아래 **Change visibility** → Public

### 「비공개 레포이거나 권한이 없습니다.」

위와 같습니다. 레포를 **공개**로 바꿔 주세요.

### 「레포 URL 형식이 올바르지 않습니다.」

**올바른 형태**

```
https://github.com/사용자명/레포이름
https://github.com/사용자명/레포이름/tree/브랜치명
```

**흔한 잘못된 입력**

| 입력 | 문제 |
|------|------|
| `github.com/사용자명` | 레포 이름이 없음 |
| 파일 하나의 주소(`.../blob/main/app.py`) | 레포 루트 주소를 넣어야 함 |
| GitLab·Bitbucket 주소 | **GitHub만** 지원 |

### 「GitHub에 연결할 수 없습니다. 네트워크 연결을 확인해 주세요.」

일시적인 네트워크 문제이거나 GitHub 장애입니다. 1~2분 뒤 다시 시도하세요.

### 「GitHub API 요청 한도에 도달했습니다.」

**왜 생기나요?**
여러 사람이 같은 서버를 통해 GitHub를 조회하면 시간당 한도에 걸립니다.
내 잘못이 아니라 **서버 공용 한도**입니다.

**어떻게 푸나요?**
**5~10분 기다렸다가** 다시 시도하세요. 계속 반복되면 운영진에게 알려 주세요.
운영진이 `GITHUB_TOKEN`을 등록하면 한도가 크게 늘어납니다.

## 3. 레포는 읽었는데 점수가 0점인 경우

### 「레포에서 기획서 파일(PLAN.md·기획서.md 등)을 찾을 수 없습니다.」 → 전 항목 0점

**왜 0점인가요?**
두 심사 분야가 **모두 기획서를 근거로** 채점합니다. 기획서가 없으면
평가할 기준 자체가 없으므로 전 항목 0점입니다.

**어떻게 푸나요?**
아래 이름 중 하나로 레포에 올리세요. 루트에 두는 것이 가장 확실합니다.

```
PLAN.md   기획서.md   planning.md   PLAN.txt   기획서.txt
```

> `제안서.md`, `보고서.md`, `README.md` 등은 기획서로 인식하지 않습니다.

### 「기획서가 무의미한 입력입니다.」

**왜 생기나요?**
글자 수가 극히 적거나, "테스트", "안녕하세요" 같은 자리표시자 문구이거나,
같은 단어만 반복되는 경우입니다.

**어떻게 푸나요?**
목적·핵심 기능·성공 기준을 갖춘 실제 기획서를 넣으세요.
분량은 최소 **80자 이상**, 실질 단어 12개 이상이 필요합니다.

### 「소프트웨어·웹앱 개발 기획서가 아닙니다.」

**왜 생기나요?**
정책 아이디어나 개념 소개만 있고 **구현 기획 요소**(요구사항, 기능, 화면,
성공 기준, 예외 처리)가 없으면 코드 심사용 기획서로 보지 않습니다.

**어떻게 푸나요?**
"무엇을 만들 것인가"를 기능 단위로 번호를 매겨 적고, 성공 기준을 덧붙이세요.

### 「기획서와 실행 코드의 주제가 일치하지 않습니다.」 → 의도 구현도 0점

**왜 생기나요?**
기획서와 코드가 서로 다른 프로젝트를 가리킬 때입니다.
결과서에 시스템이 인식한 주제 목록이 함께 표시됩니다.

**어떻게 푸나요?**
같은 프로젝트의 기획서와 코드를 한 레포에 두세요.
예전 과제의 기획서가 남아 있지 않은지 확인해 보세요.

### 「레포에서 실행 코드(소스 파일)를 찾을 수 없습니다.」

**왜 생기나요?**
문서만 있고 소스 파일이 없거나, 소스가 전부 제외 대상 폴더
(`node_modules`, `.venv`, `dist`, `build` 등)에 들어 있는 경우입니다.

**어떻게 푸나요?**
앱 진입점(`app.py`, `index.html`, `main.js` 등)을 레포에 포함해 커밋하세요.
`.gitignore`가 소스를 통째로 빼고 있지 않은지도 확인해 보세요.

## 4. 점수가 예상보다 낮은 경우

### 제1분야만 낮다

기획서의 문제 정의가 약하다는 뜻입니다.

- **기관용**: 공공 현장의 문제를 구체적으로, 보안·개인정보·예산 등 적용 전제를 함께
- **기업용**: 문제 규모를 **시간·건수·금액**으로 환산해서

### 기업용에서 「자체 구축 정당성」이 특히 낮다

**가장 흔한 감점 지점입니다.** 엑셀·노션·기성 SaaS로 대체 가능해 보인다는 뜻입니다.

기획서에 **왜 직접 만들어야 하는지**를 적으세요. 예를 들면 사내 데이터 접근 권한,
기존 시스템 연동, 망 분리·보안 제약, 라이선스 비용, 조직 고유 업무 규칙 같은
구체적 근거입니다. 검토한 대안과 배제 사유를 표로 적으면 가장 확실합니다.

### 「의도 구현도」만 낮다

기획서에 적은 기능이 코드에 없다는 뜻입니다.
기능을 10개 적고 3개만 구현하면 이 분야가 크게 깎입니다.
만들지 않을 기능은 **범위 밖**으로 빼서 적으세요.

### 「판정 불안정」 표식이 붙었다

같은 항목을 3회 채점했는데 **점수 편차가 컸다**는 표시입니다.
기획서 서술이 모호해 해석이 갈렸을 가능성이 큽니다.
해당 항목과 관련된 내용을 더 명확히 적어 보세요. 오류는 아닙니다.

## 5. 심사 도중 문제

### 결과가 안 나오고 계속 기다린다

정상 소요 시간은 **40초~2분**입니다. 진행 단계 표시가 멈춘 것처럼 보여도
「앙상블 채점」 단계에서 시간이 가장 오래 걸립니다.

**버튼을 여러 번 누르지 마세요.** 누를 때마다 새 심사 요청이 들어가
대기가 길어지고 한도 초과를 유발합니다.

### 「심사 도중 연결이 끊어졌습니다.」

네트워크가 끊겼거나 브라우저 탭이 백그라운드에서 정지된 경우입니다.
탭을 켜 둔 채로 다시 시도하세요.

### 「OpenAI API 키가 설정되지 않아 심사를 진행할 수 없습니다.」

서버 설정 문제입니다. 이용자가 해결할 수 없으니 **운영진에게 알려 주세요.**

### 음성 브리핑이 재생되지 않는다

음성은 **부가 기능**입니다. 합성에 실패하면 대본 텍스트만 표시되며,
**점수와 총평은 그대로 유효**합니다. 브라우저 자동재생 차단 설정도 확인해 보세요.

## 6. 자주 오해하는 것

| 오해 | 실제 |
|------|------|
| README를 잘 써야 점수가 오른다 | README는 **채점 대상이 아닙니다** |
| Python으로만 제출해야 한다 | **언어 무관**입니다 |
| 파일 3개를 업로드해야 한다 | 이제 **레포 주소 하나만** 냅니다 |
| 코드를 한 파일로 합쳐야 한다 | 여러 파일을 **최대 25개까지** 읽습니다 |
| 두 트랙 점수를 비교할 수 있다 | **비교 불가.** 기준이 다릅니다 |
| AI가 앱을 실행해 본다 | 실행하지 않고 **글만 읽습니다** |
| 모듈 분리·예외 처리는 과잉 구현이다 | **합리적 보완은 감점 사유가 아닙니다** |
